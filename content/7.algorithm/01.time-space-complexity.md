先说说什么是算法：算法（Algorithm）是指用来操作数据、解决程序问题的一组方法。

对于同一个程序问题，使用不同的算法，也许最终得到的结果一样，但是程序执行过程中消耗的资源和时间却会有很大的区别。

所以我们通过下面两个维度去衡量算法的优劣：

- 时间复杂度：程序执行当前算法所消耗的时间。
- 空间复杂度：程序执行当前算法所需要占用的内存空间。

然而，时间和空间往往会面临鱼和熊掌不可兼得，所以我们需要在算法中取一个平衡点。

## 时间复杂度

顾名思义，就是程序运行算法所需要花费的时间。运行时间越短，效率越高，运行时间越长则效率越低。

我们来学习如何计算这个时间复杂度，很多人想的是把这个算法程序运行然后计算时间即可，但是我们得考虑运行环境，比如在不同配置的电脑上运行结果相差很大。

我们假设每一行代码的运行时间都为1 Btime，那么算法的总运行时间 = 运行的总代码行数。

下面我们来看一下这段代码（提供了各种语言的例子）：

::code-group
```python [Python]
def dogeggs_sum (n):
  sum = 0
    
  for dogegg in range(n):
    sum += dogegg
  return sum
```

```

```

在上面假设的情况下，这段累加求和的d代码总的运行时间是多少呢？

- 第二行代码需要 1 Btime 的运行时间，赋值操作。
- 第四和第五行代码分别运行了n次，所以这两行各需要n * Btime的运行时间。

所以总的运行时间就是 (1+2n) * Btime。

我们一般用 T 函数来表示总运行时间，所以上面总的运行时间就可以表达为：

- T(n) = (1+2n)*Btime。

没错，n我们用来表示数据量，有些人也叫数据集，参数。

通过上面公式，我们发现T(n)和代码执行行数（次数）成正比关系，发现这个规律很重要，因为这告诉我们数据量和运行时间之间有正向趋势！

所以，前人想到了大```O```表示法，不是用来计算算法的运行时间，而是用表示计算趋势的。

- ```T(n)=O(f(n))```

n作为数据量大小，它可以取1，100，10000甚至更大的数，这时你会发现，当数据量越来越大时，你会发现代码中的某些部分的```失效```了。

还是以上面代码为例，当n=1000时，1+2n = 2001；当n=10000时，1+2n=20001，当n持续增大时，常数1和系数2对于最后的结果越来越没存在感了，即对趋势的变化影响不大。

这里常数1影响很小我们容易理解，但是系数2我们常常不理解，明明是2n增长感觉上会很明显才对，我们来捋一下。

大 O 不是用来比较：`2n` 和 `1n` 谁更快。
它是用来区分：**当 n 越来越大时，总量是以什么形式暴涨**，如果还不懂，在下面我们会进一步解释。

看完下面两段代码进一步学习一下求时间复杂度。

def dogeggs_sum (n):
