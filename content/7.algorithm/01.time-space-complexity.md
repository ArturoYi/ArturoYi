先说说什么是算法：算法（Algorithm）是指用来操作数据、解决程序问题的一组方法。

对于同一个程序问题，使用不同的算法，也许最终得到的结果一样，但是程序执行过程中消耗的资源和时间却会有很大的区别。

所以我们通过下面两个维度去衡量算法的优劣：

- 时间复杂度：程序执行当前算法所消耗的时间。
- 空间复杂度：程序执行当前算法所需要占用的内存空间。

然而，时间和空间往往会面临鱼和熊掌不可兼得，所以我们需要在算法中取一个平衡点。

## 时间复杂度

顾名思义，就是程序运行算法所需要花费的时间。运行时间越短，效率越高，运行时间越长则效率越低。

我们来学习如何计算这个时间复杂度，很多人想的是把这个算法程序运行然后计算时间即可，但是我们得考虑运行环境，比如在不同配置的电脑上运行结果相差很大。

我们假设每一行代码的运行时间都为1 Btime，那么算法的总运行时间 = 运行的总代码行数。

下面我们来看一下这段代码（提供了各种语言的例子）：

::

在上面假设的情况下，这段累加求和的d代码总的运行时间是多少呢？

- 第二行代码需要 1 Btime 的运行时间，赋值操作。
- 第四和第五行代码分别运行了n次，所以这两行各需要n * Btime的运行时间。

所以总的运行时间就是 (1+2n) * Btime。

我们一般用 T 函数来表示总运行时间，所以上面总的运行时间就可以表达为：

- T(n) = (1+2n)*Btime。

没错，n我们用来表示数据量，有些人也叫数据集，参数。

通过上面公式，我们发现T(n)和代码执行行数（次数）成正比关系，发现这个规律很重要，因为这告诉我们数据量和运行时间之间有正向趋势！

### 大 O 表示法

所以，前人想到了大```O```表示法，不是用来计算算法的运行时间，而是用表示计算趋势的。

- ```T(n)=O(f(n))```

n作为数据量大小，它可以取1，100，10000甚至更大的数，这时你会发现，当数据量越来越大时，你会发现代码中的某些部分的```失效```了。

还是以上面代码为例，当n=1000时，1+2n = 2001；当n=10000时，1+2n=20001，当n持续增大时，常数1和系数2对于最后的结果越来越没存在感了，即对趋势的变化影响不大。

这里常数1影响很小我们容易理解，但是系数2我们常常不理解，明明是2n增长感觉上会很明显才对，我们来捋一下。

大 O 不是用来比较：`2n` 和 `1n` 谁更快。
它是用来区分：**当 n 越来越大时，总量是以什么形式暴涨**，如果还不懂，在下面我们会进一步解释。

我们一点点来计算时间负责度。

- 第二行代码需要运行 1 次。
- 第四行代码需要运行 n 次。
- 第五行代码需要运行 n² 次。
- 第六行带啊也需要运行 n² 次。

所以总的运行次数 f(n) = 1 + n + 2n² 。

当 n = 5 时，f(n) = 1 + 5 + 2* 25。
当 n = 10000时，f(n) = 1 + 10000 + 2 * 100000000。

注意到了吗，很明显可以看出 n² 对程序运行次数起到了决定性作用。

反倒常熟 1，系数 2 对最终结果（即趋势）影响不大，我们可以把气忽略掉，总而言之： ```在分析一个算法、一段代码的时间复杂度时，也只关注循环执行次数最多的那一段代码即可```。

所以我们得到下面结果：

| 表达式 | 大 O 类型 | n=10 | n=100 | n=1000 | 特点 |
| --- | --- | --- | --- | --- | --- |
| `1+2n` | `O(n)` 线性 | 21 | 201 | 2001 | 随 n 等比例增长 |
| `1+n+2n²` | `O(n²)` 平方 | 211 | 20101 | 2001001 | 随 n 平方暴涨 |

大 O 时间复杂度实际上并不具体表示代码真正的执行时间，而是表示「代码执行时间随数据规模增长的变化趋势」，所以，复杂度的计算方法遵循以下几个原则：

- 复杂度与具体的常系数无关，例如O(n) 和 O(2n) 表示的是同样的复杂度。
- 「多项式级的复杂度相加的时候，选择高者作为结果」，例如 O(n²)+O(n) 和 O(n²) 表示的是同样的复杂度。

### 常见时间复杂度

算法学习过程中，我们会遇到各种各样的时间复杂度，当常见的时间复杂度都在下面之列：

| 复杂度 | 名称 | 增长特点 | 典型例子 |
| --- | --- | --- | --- |
| `O(1)` | 常数复杂度 | 输入再大，操作次数不变 | 取数组第 k 个元素；简单加减赋值 |
| `O(log n)` | 对数复杂度 | n 翻倍，只多固定几步，增长极慢 | 从 1 开始每次乘 2 |
| `O(n)` | 线性复杂度 | 操作数和 n 成正比 | 遍历一次数组，单循环 |
| `O(n log n)` | 线性对数 | 比线性慢、比平方快 | 归并排序、快速排序（平均） |
| `O(n²)` | 平方复杂度 | n 扩大 10 倍，工作量 ×100 | 双层 for 循环，冒泡排序 |
| `O(n³)` | 立方复杂度 | n 扩大 10 倍，工作量 ×1000 | 三层嵌套循环 |
| `O(2ⁿ)` | 指数复杂度 | n 稍微增加，计算量爆炸 | 暴力枚举全部子集；朴素递归求斐波那契 |
| `O(n!)` | 阶乘复杂度 | 比指数增长更快，n 很小就跑不动 | 全排列暴力枚举 |

其中复杂度大小比较：

`O(1)` < `O(log n)` < `O(n)` < `O(n log n)` < `O(n²)` < `O(n³)` < `O(2ⁿ)` < `O(n!)`

下面每个复杂度我们看一下。例子都按同一件事来写，方便对照循环是怎么把规模抬上去的。

#### O(log n) 对数：每次翻倍

dogegg 从 1 开始，每次乘 2，直到不小于 n。循环转几圈，就是 `log2(n)`。

```python [Python]
def dogegg_double(n):
  dogegg = 1              # 从 1 开始

  while dogegg < n:       # 还没长到 n，就再乘一次 2
    dogegg = dogegg * 2   # 1 → 2 → 4 → 8，圈数就是 log2(n)
  return dogegg
```

dogegg 的变化是 1 → 2 → 4 → 8 → …。每转一圈就多乘一个 2，停下来时，是 x 个 2 连乘，结果不小于 n：

`2 × 2 × … × 2 >= n`

这 x 个 2 连乘，就是 2 的 x 次方对应 n：

`2ˣ >= n`

两边取以 2 为底的对数，圈数就是：

`x = log2(n)`

n 正好是 2 的整数次方时等号成立。对不齐时，x 比 `log2(n)` 略大，向上取整，趋势不变。

- n = 8：`2 × 2 × 2 = 8`，x = 3，也就是 `log2(8) = 3`
- n 大约 1000：`2¹⁰ = 1024`，x 大约 10
- n 大约 100 万：`2²⁰ ≈ 104万`，x 大约 20

n 从 1000 涨到 100 万，圈数只从大约 10 变成大约 20。底数是 2 还是 10 不用写进大 O，换底只差一个固定倍数，固定倍数会被抹掉，所以写成 `O(log n)`。

#### O(n log n) 线性对数：归并排序

先把数组对半拆开，拆到底再两两合并。拆分大约有 log n 层，每一层都要把 n 个数扫一遍，合起来就是 O(n log n)。归并排序每次都是这个量级。

::code-group
```python [Python]
def merge_sort(nums):
  if len(nums) <= 1:
    return nums
  mid = len(nums) // 2
  left = merge_sort(nums[:mid])
  right = merge_sort(nums[mid:])
  merged = []
  i = j = 0
  while i < len(left) and j < len(right):
    if left[i] <= right[j]:
      merged.append(left[i])
      i += 1
    else:
      merged.append(right[j])
      j += 1
  merged.extend(left[i:])
  merged.extend(right[j:])
  return merged
```

```kotlin [Kotlin]
fun merge_sort(nums: List<Int>): List<Int> {
    if (nums.size <= 1) return nums
    val mid = nums.size / 2
    val left = merge_sort(nums.subList(0, mid))
    val right = merge_sort(nums.subList(mid, nums.size))
    val merged = mutableListOf<Int>()
    var i = 0
    var j = 0
    while (i < left.size && j < right.size) {
        if (left[i] <= right[j]) {
            merged.add(left[i])
            i++
        } else {
            merged.add(right[j])
            j++
        }
    }
    merged.addAll(left.subList(i, left.size))
    merged.addAll(right.subList(j, right.size))
    return merged
}
```

#### O(n²) 平方：冒泡排序

相邻两个数比大小，较大的往后换。外层走 n 轮，内层每一轮也跟着 n 走，所以是平方复杂度。n 扩大 10 倍，比较次数大约变成 100 倍。下面的实现会改原数组。

::code-group
```python [Python]
def bubble_sort(nums):
  n = len(nums)
  for i in range(n):
    for j in range(n - 1 - i):
      if nums[j] > nums[j + 1]:
        nums[j], nums[j + 1] = nums[j + 1], nums[j]
  return nums
```

```kotlin [Kotlin]
fun bubble_sort(nums: IntArray): IntArray {
    val n = nums.size
    for (i in 0 until n) {
        for (j in 0 until n - 1 - i) {
            if (nums[j] > nums[j + 1]) {
                val tmp = nums[j]
                nums[j] = nums[j + 1]
                nums[j + 1] = tmp
            }
        }
    }
    return nums
}
```

```swift [Swift]
func bubble_sort(_ nums: [Int]) -> [Int] {
    var nums = nums
    let n = nums.count
    for i in 0..<n {
        for j in 0..<(n - 1 - i) {
            if nums[j] > nums[j + 1] {
                nums.swapAt(j, j + 1)
            }
        }
    }
    return nums
}
```

#### O(n³) 立方：朴素矩阵乘法

两个 n×n 的矩阵相乘，结果里一共有 n² 个格子，每个格子都要做 n 次乘加。三层循环套在一起，就是 O(n³)。n 扩大 10 倍，工作量大约变成 1000 倍。

::code-group
```python [Python]
def multiply(a, b):
  n = len(a)
  c = [[0] * n for _ in range(n)]
  for i in range(n):
    for j in range(n):
      for k in range(n):
        c[i][j] += a[i][k] * b[k][j]
  return c
```

#### O(n!) 阶乘：全排列

n 个互不相同的元素，第一个位置有 n 种选法，第二个位置剩 n − 1 种，一直乘到 1。路径总数就是 n!。n = 10 已经是三百多万，n = 12 接近 5 亿，所以只能枚举很小的 n。

::code-group
```python [Python]
def permutations(nums):
  result = []
  used = [False] * len(nums)
  path = []

  def dfs():
    if len(path) == len(nums):
      result.append(path[:])
      return
    for i in range(len(nums)):
      if used[i]:
        continue
      used[i] = True
      path.append(nums[i])
      dfs()
      path.pop()
      used[i] = False

  dfs()
  return result
```

```kotlin [Kotlin]

    val result = mutableListOf<List<Int>>()

        if (path.size == nums.size) {

            used[i] = true
            path.add(nums[i])
```

### 平均复杂度

除了数据规模影响算法的运行时间，“数据的具体情况”也会运行到运行时间。

我们来看这么一段代码：

::code-group

::

上面这段代码是求变量 word 在列表lst中出现的位置，我用这段来解释“数据的具体情况”是什么意思。

拿 `lst = ['a', 'b', 'c', 'd']` 来数一遍。循环碰到 `word` 就 `break`，所以比几次完全看 `word` 落在哪：

| word | 停在哪 | 循环次数 |
| --- | --- | --- |
| `'a'` | 第 1 个就命中 | 1 |
| `'b'` | 第 2 个命中 | 2 |
| `'c'` | 第 3 个命中 | 3 |
| `'d'` | 最后一个才命中 | 4 |
| `'e'` | 列表里没有，只能走完 | 4 |

- 第 1 个就命中时，后面都不用看，这是最好情况，时间复杂度是 O(1)。
- `word` 在末尾，或者像 `'e'` 这样根本不在列表里，都要把整个列表走完，这是最坏情况，时间复杂度是 O(n)。

这就是数据具体情况不同，代码的时间复杂度不同。我们得出下面 3 种情况：

- 最好时间复杂度：就是在最理想情况下，代码的时间复杂度，比如对应上例变量 word 正好是列表 lst 的第 1 个，这个时候对应的时间复杂度 O(1) 就是这段代码的最好情况时间复杂度。
- 最坏时间复杂度：最坏情况的情况下，代码的时间复杂度，对应上例变量 word 正好是列表 lst 的最后一个，或者 word 不存在于列表 lst，这个时候对应的时间复杂度 O(n) 是这段代码的最坏情况时间复杂度。
- 平均时间复杂度：大多数情况下，代码执行情况介于最好和最坏之间，所以出现了平均情况时间复杂度。

那么怎么计算平均时间复杂度呢？需要用到概率论的知识。

我们还是用什么的例子来讲：

- 从大的方面来看，查找变量x在列表 lst中的位置有两中情况，在或者不在。假设两种情况的概率都为 1/2。
- 如果 x 出现在列表 lst 中，那么 x 有 n 种情况，它有可能出现在 0 到 n-1中的任意位置，假设出现在每个位置的概率都相同，都为 1/n。

每个出现的概率（即权重）知道了，所以平均时间复杂度为：

「在列表里」的概率是 `1/2`，这一半还要再平分给 `n` 个位置，所以 `x` 落在某一个具体位置的概率是 `1/2 × 1/n = 1/(2n)`。不在列表里的概率仍然是 `1/2`。

落在第 1 个位置要循环 1 次，第 2 个位置要循环 2 次，一直到第 `n` 个位置要循环 `n` 次；不在列表里也要循环 `n` 次。平均循环次数就是这些情况的加权和：

::accordion

:::accordion-item{label="什么是加权平均值？" icon="i-lucide-scale" class="!text-default"}
普通平均是每个数权重一样：加起来，再除以个数。加权平均是每个数先乘自己的权重，再相加。权重大的数把结果拉得更近。

三次考试可以看出来：

- 平时 60 分，权重 `0.2`
- 期中 80 分，权重 `0.3`
- 期末 90 分，权重 `0.5`

加权平均是 `60×0.2 + 80×0.3 + 90×0.5 = 81`。普通平均是 `(60+80+90)/3 ≈ 76.7`。期末占了一半权重，所以 81 更靠近 90，而不是停在三个分数的正中间。

权重必须加起来等于 1（这里 `0.2 + 0.3 + 0.5 = 1`）。这时加权和本身就是平均值，不用再除一次。

上面公式里，循环次数是要平均的数，出现概率就是权重。`n` 个位置各占 `1/(2n)`，再加上「不在列表里」的 `1/2`，权重正好加总为 1，所以 `T(n)` 直接就是平均循环次数。
:::
::

- `T(n) = 1×1/(2n) + 2×1/(2n) + … + n×1/(2n) + n×1/2`
- `= (1 + 2 + … + n) / (2n) + n/2`
- `= n(n+1) / (4n) + n/2`
- `= (n+1)/4 + n/2`
- `= (3n+1)/4`

`(3n+1)/4` 里，系数 `3/4` 和常数 `1/4` 都不改变增长趋势，所以平均时间复杂度是 `O(n)`。

大多情况下，我们考虑最差时间复杂度，因为考虑最坏的结果，保障代码的最低下限。

## 空间复杂度

空间复杂度和时间复杂度一样，反映的也是一种趋势，是指代码运行过程中临时变量占用的内存空间。

代码在计算机中运行所占用的存储空间主要分为 3 部分：

- 代码本身所占用的
- 输入数据所占用的
- 临时变量所占用的

前面两个部分是本身就要占用这些空间，与代码性能无关，所以我们在衡量代码的空间复杂度时，只关心运行过程中临时占用的内存空间。

空间复杂度记作：S(n),表达形式与时间复杂度一样：

S(n) = O(f(n))

在这里  n 作为数据集大小，f(n)指的是规模 n 所占存储空间的函数。

我们用下面代码来学习如何分析空间复杂度：
