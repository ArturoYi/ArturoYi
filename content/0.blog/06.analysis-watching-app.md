这份笔记拆一个海外社交、休闲向的观看类安装包：页面和直播怎么分层，代码和资源怎么保护。样本不是头部产品，结论用来对照自己的实现。

::note
只记安装包里能直接对上的东西：目录、清单、dex、so 和内置资源。包名和应用名不写入正文。抓包过程不写。
::

## 目录里的技术栈

| 部分 | 证据 | 对应功能 |
| --- | --- | --- |
| Flutter | `libflutter.so` 在 `lib/`，没有 `libapp.so`；能看到 `flutter_inappwebview` | 主要页面 |
| Vue | `assets/live_h5/` | 直播间。页面能在本地打开，没有数据 |
| 声网 | `libagora-*.so`；`io.agora.rtc2.RtcEngine`、`io.agora.chat.ChatClient` | 实时音视频和聊天 |
| 原生 | `classes.dex`，壳文件和各 ABI 的 so 在 `assets/` | 启动，以及选图、扫码、支付这些组件 |

```text [attachBaseContext]
            mInitialApplication   换成真实 Application 实例
            mBoundApplication     改 AppBindData 里的 Application 信息
            mApplication          改 LoadedApk 里的引用
            mAllApplications      全局列表里换掉壳 Application
            makeApplication       创建真实 Application 实例
    ↓
installContentProviders()                    在 onCreate 之前，所以还原必须已经完成
    ↓
ProxyApplication.onCreate()                  关键拦截点②
    └─ 调真实 Application.onCreate()
          此时 DEX 已在内存里还原，业务类可以加载
    ↓
系统正常创建 Activity / Service / Receiver
    经过 ProxyComponentFactory，确保用还原后的 ClassLoader
```

系统只从 `lib/<abi>/` 加载 so。这个包把两份关键库放在默认路径之外：壳的加载器在 `assets/vwwwwwvwww/`，四个 ABI 各一份；Flutter 的 `libapp.so` 也不在 `lib/`。系统不会自己去读 `assets/` 里的 so。

`attachBaseContext` 是进程里最早能插手的回调。壳在这里还原 DEX 函数体，把真实 `Application` 换回去，后面 Flutter 和各个页面才起来。`ProxyComponentFactory` 保证随后创建 Activity、Service、Receiver 时，用的仍是还原后的 ClassLoader。

静态打开清单，`android:name` 上是壳。so 里能看到 `dpt::reflect`，反射目标是 `DexPathList`、`ActivityThread`、`LoadedApk`。dex 里有 `JniBridge`、`dpt-shell`，以及字符串 `dpt-shell seem not working`。

::warning
壳挡住的是启动入口。Flutter 资源、内置 H5 和声网的 Java 层仍然是明文。
::

## 资源和原生库

图片、网页、Flutter 资源和对外发布的 so 大多还是明文，分开放在 `res/`、`assets/` 和 `lib/`。

### `res/`

图片、布局和 xml 都在。根上的文件名收成 `-F.xml`、`06.png` 这种短名，`color/` 仍是库的原名。大约 711 个 xml、247 张 png，另有几张 webp、一条 wav、一条 ogg。

业务域名和密钥不在 `res/`。xml 里的 http 几乎都是 Android 的 schema。`resources.arsc` 里另有 ZXing 的 `journeyapps.com`。网络安全配置在 `res/HP.xml`，文件名已经看不出用途。

### `assets/`

内置网页在这里。`live_h5/index.html` 是 Vue 直播间，支付走清单里的 `PayH5Activity`。Flutter 资源在 `flutter_assets/`，图片文件名已经能看出金币、会员、漫画和短视频。`flutter_assets/assets/video/x.mp4` 是一段内置视频。

域名和密钥也在 `assets/`。`flutter_assets/lib/net/` 打进了四份 Dart 源码，`HostProvider.dart` 里有域名。`rsa_public_key.pem` 是 1024 位 RSA 公钥，文件里是一行 Base64。`dexopt/baseline.prof` 是交给系统的启动配置，不是子 dex。`assets/` 里没有明文 `.dex`。

对不上格式的几份在 `assets/` 根上：`d_shell_data_001`、`OoooooOooo`、`vlllllvlll/`，以及 `vwwwwwvwww/` 下四个 ABI 的加载器 so。

### `lib/`

对外发布只带了 `arm64-v8a`，没有 `armeabi-v7a`。清单里 `extractNativeLibs="true"`，安装时会把这一层解出来。壳的加载器仍是四个 ABI，放在 `assets/vwwwwwvwww/`，不在 `lib/`。`org.apache.http.legacy` 和 `androidx.window` 是可选系统库，不在下表这些 so 里。

| 文件 | 大约体积 | 作用 |
| --- | --- | --- |
| `libagora-rtc-sdk.so` | 14MB | 声网实时音视频，直播推拉流的主体 |
| `libflutter.so` | 10MB | Flutter 引擎 |
| `libagora-chat-sdk.so` | 7MB | 声网聊天 |
| `libagora_ffmpeg.so`、`libagora-soundtouch.so`、`libaosl.so` | 合计约 1.5MB | 声网自带的解码、变声和基础库 |
| `libvideo_dec.so` | 1.2MB | 短视频解码，和声网那组分开 |
| `libwebcrypto.so` | 1.2MB | 给 WebView 页面用的加密库，和内置浏览器放在一起 |
| `libcipherdb.so` | 1.1MB | 本地加密库（SQLCipher） |

声网相关库加上 Flutter 引擎，占了这个包体积的大头。

## 打进包里的 Dart

`flutter_assets/lib/net/` 下面是 Dart 源码，不是编译产物。这几份把客户端的做法露在外面：

- `HostProvider`、`HostComicProvider`：域名池。一条失败就换下一条，本地还存一份加密后的列表。出海域名被封时会用到换域名，名单本身不该留在包里。
- `token_interceptor.dart`：刷新登录态。请求头里带设备号、系统版本和会话号。注释里还留着生成代码时的标记。
- `user_email_repository.dart`：邮箱验证码和绑定。海外包用邮箱做账号，少一笔短信费。

`assets/rsa_key/rsa_public_key.pem` 是放在客户端的 RSA 公钥，文件里一行 Base64，对应 1024 位。

::warning
Release 包不该把这些源码打进 `assets/`。域名池、刷新登录的字段和公钥都因此露在外面。公钥可以放在客户端，1024 位现在偏短。
::

## 直播间 H5

`manifest.json` 写明这是 `live-h5`，版本 1.6.1，引擎 Vue 3，入口 `index.html`。样式表按房间、聊天、消息、个人页、充值、兑换、关播、预览拆开。另有一份 `home-ios-fix.css`，同一套页面也给 iOS 的 WebView。

::tip
房间界面走 H5，更新房间不用等商店审核。Flutter 负责首页、会员、金币和工具页。`LiveContainerActivity` 装这场 H5，`PayH5Activity` 单独装支付页。
::

`js/ticket.js` 配上充值和兑换，房间里的货币和外面的金币是连着的。

声网在原生层。`lib/` 里是 `libagora-rtc-sdk.so`、`libagora-chat-sdk.so`，`classes.dex` 里是 `io.agora.rtc2.RtcEngine` 和 `io.agora.chat.ChatClient`。H5 的 `app.js` 没有 Agora Web SDK，只把 `agoraAppId` 和主播 uid 放进房间数据，再通过 `window.NativeBridge.postMessage` 交给原生。进频道的 `joinChannel` 在 dex 里。

## 请求保护

::note
只根据安装包里的源码、配置和符号来对。抓包过程不写。
::

线上请求叠了四层：TLS、应用层整包加密、设备画像、动态域名。四层都在，强度差很多。

```text [请求四层]
H5 Q() / Flutter HttpUtils
    ↓
NativeBridge.http_request 或 Dio
    ↓
① TLS          https://当前域名/...          通道
② 整包加密      JSON → encryption → {encrypt}  应用层
③ 设备画像      请求头 + tips                   绑定会话
④ 域名池        HostProvider 失败换下一条        抗封
    ↓
响应：不像 JSON 就 aesDecrypt，像 JSON 就当明文
```

### TLS

`HostProvider` 探测接口拼的是 `https://${currentHost}/sf51/domain/app.version`。通道走 HTTPS。

这一层在包里被削薄了两处。`res/HP.xml` 是网络安全配置，文件名看不出用途，`base-config` 把 `cleartextTrafficPermitted` 设成 `true`，系统允许明文 HTTP。dex 里有 OkHttp 自带的 pinning 报错文案，没有 `CertificatePinner`，配置里也没有 `pin-set`。域名池还混了 `IP:端口`，按 IP 访问时证书对不上域名。`CustomSSLSocketFactory` 来自 `video_player` 插件，不是业务自己做的证书固定。

::warning
通道是 HTTPS，对端没有钉死。它挡得住传输路上的随意查看，挡不住主动替换证书的中间人。
::

### 应用层整包加密

刷新登录这一条把组包写在明面上。业务对象先编成 JSON，再交给 `JhEncryptUtils.encryption`，POST 的 body 只剩一个 `encrypt` 字段。回包走 `JhEncryptUtils.aesDecrypt`。拦截器对响应先看一眼：字符串已经以 `{` 开头，就当明文 JSON；否则再解密。

材料对得上。`assets/rsa_key/rsa_public_key.pem` 是一行 Base64，解开是 162 字节的 SubjectPublicKeyInfo，对应 1024 位 RSA。dex 里有 `RSA/ECB/PKCS1Padding` 和 `AES/CBC/PKCS7Padding`。清单里的 `APP_CDN_URL` 是一段 RSA 密文，不是明文域名。本地还有 `JhAESStorageUtils`，域名列表、版本号、绑定邮箱都加密后落盘。`libcipherdb.so` 是 SQLCipher，管本地库，不管线上的包。

出口并不都套这层。漫画的 `HostComicProvider` 对传入 URL 直接 GET，超时 20 秒，没有 `encrypt` 字段。H5 自己不做 AES / RSA，加解密只在原生桥这一侧。

::warning
公钥放在客户端说得通，1024 位配合 PKCS#1 v1.5 现在偏短。拦截器还给密文留了明文回退：服务端一旦回 JSON，应用层加密就不起作用。真正的 `JhEncryptUtils` 在 `flutter_base` 里，这份源码没打进包。调用点、公钥和字段名已经足够把形状看清楚。
::

### 设备画像

`token_interceptor` 刷新登录态时，请求头带一组设备画像：`device`、`device_id`、`device_fingerprint`、`fp_version`、`sid`、`client_ts`，再加上品牌、型号、系统版本和 analytics SDK 版本。body 里是 `mac`（Android ID）、渠道号，以及 `tips`。`tips` 由 `macct + androidId + os` 做一次 MD5。

这是把会话钉在设备画像上，方便服务端认机、限设备和踢登录。它不参与密钥派生。请求头里已经有同样的标识，`tips` 只是再哈希一次。换机或改这些字段，服务端可以拒绝。同一台设备上重放已经拿到的包，它拦不住。

### 域名轮换

`HostProvider` 取域名分三档。本地有就用本地；没有就解一份 AES 列表；再没有就用写进源码的 `cdnString`。列表里是若干 `.cc` 域名和一组 `IP:端口`。其后是上次拉下来的 `APP_API_DOMAIN`，还空就落到内置兜底。当前下标对应哪条，失败就换下一条。探测路径固定为 `/sf51/domain/app.version`，后面拼本地版本号。

出海被封时需要换域名。三档里最不该进包的那一档进了包：明文域名池、AES 列表的解法，以及兜底域名的读取路径，都写在打进 `assets/` 的 Dart 里。轮换可以留，名单不该跟着安装包走。

四层里，真正在起作用的是应用层整包和域名轮换。TLS 开了明文口，设备画像只是附加字段。壳保的是启动入口，这四层保的是线上的包。两边都把不该明文的东西留在了 `flutter_assets`。

## 对照自己的实现

代码保护做了两件事：壳换掉启动入口，再把一部分函数体拆出去。按 dex 头打开，只能看到壳。加载器放在 `assets/`，运行时再把业务 dex 和抽走的函数体填回去。Flutter 的 `libapp.so` 也不在默认路径。

主 dex 的另一份以未压缩 zip 留在 `classes.dex` 尾部，指令是完整的。被拆走的是 `classes2` 的函数体。自己的类名打乱了。直播 SDK、声网和 Flutter 插件仍是原名。

值得对照的是分层。房间走 H5，首页和工具页走 Flutter，支付单独一个 Activity。域名失败可以换下一条，名单要放在包外。壳只盖住启动入口。Dart 源码、H5、声网的 Java 层，以及域名和请求形状，都还在 `flutter_assets` 里。
