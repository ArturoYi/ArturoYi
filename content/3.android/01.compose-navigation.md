用 Jetpack Navigation Compose（2.8+）的类型安全 API 在页面之间跳转：用 `@Serializable` 路由替代字符串 path，在编译期发现拼写和参数类型错误。

::note
前半是 **Navigation 2** 的类型安全 `NavHost`，单图、单返回栈时用它就够。后半是记账应用里的 **Navigation 3**：两个首页标签各一条返回栈，宽屏列表和详情并排。两套 API 各写各的图，不要在同一个宿主里混用 `composable<T>` 和 `entry<T>`。
::

## 添加依赖

类型安全路由依赖两件事：`navigation-compose` 2.8.0 及以上，以及 **Kotlin Serialization** 插件与 JSON 运行时。先在 Version Catalog 里固定版本，再在 app 模块启用插件并声明依赖。版本号以 [AndroidX Navigation 发布说明](https://developer.android.com/jetpack/androidx/releases/navigation) 为准。

```toml [gradle/libs.versions.toml]
[versions]
navigationCompose = "2.9.0"
kotlinxSerializationJson = "1.8.1"

[libraries]
androidx-navigation-compose = { group = "androidx.navigation", name = "navigation-compose", version.ref = "navigationCompose" }
kotlinx-serialization-json = { group = "org.jetbrains.kotlinx", name = "kotlinx-serialization-json", version.ref = "kotlinxSerializationJson" }

[plugins]
kotlin-serialization = { id = "org.jetbrains.kotlin.plugin.serialization", version.ref = "kotlin" }
```

在 app 模块应用插件并引入库：

```kotlin [app/build.gradle.kts]
plugins {
    alias(libs.plugins.kotlin.serialization)
}

dependencies {
    implementation(libs.androidx.navigation.compose)
    implementation(libs.kotlinx.serialization.json)
}
```

::tip
`kotlin-serialization` 必须加在**定义路由的模块**上。只加 `kotlinx-serialization-json` 而不启用插件，`@Serializable` 不会生成序列化器，编译会失败。
::

## 定义类型安全的路由

把每个目的地写成可序列化的 Kotlin 类型，而不是 `"home"`、`"profile/{id}"` 这类字符串。无参页面用 `object`，需要参数的页面用 `data class`。参数只放轻量、可序列化的值（原始类型、枚举、短字符串），不要把整个领域模型塞进路由。

```kotlin [navigation/AppRoute.kt]
import kotlinx.serialization.Serializable

@Serializable
object Home

@Serializable
object Login

@Serializable
data class Profile(val userId: String)

@Serializable
data class Search(val query: String = "")
```

规模变大时，用 `sealed interface` 把路由收拢到一处，避免散落的顶层类型：

```kotlin [navigation/AppRoute.kt]
import kotlinx.serialization.Serializable

@Serializable
sealed interface AppRoute {
    @Serializable
    data object Home : AppRoute

    @Serializable
    data class Profile(val userId: String) : AppRoute
}
```

::warning
导航参数会写入系统 `SavedState`。不要传递大型列表、Bitmap 或整个网络响应对象；页面之间只传 ID，在目的地用 Repository 或 ViewModel 再取数据。
::

## 搭建 NavHost 与起始页

在根 Composable 里创建 `NavController`，用 `NavHost` 声明图，并把 `startDestination` 设成起始路由类型。`composable<T>` 的类型参数就是目的地，不再传 route 字符串。

```kotlin [navigation/AppNavHost.kt]
import androidx.compose.runtime.Composable
import androidx.navigation.compose.NavHost
import androidx.navigation.compose.composable
import androidx.navigation.compose.rememberNavController
import androidx.navigation.toRoute

@Composable
fun AppNavHost() {
    val navController = rememberNavController()

    NavHost(
        navController = navController,
        startDestination = Home,
    ) {
        composable<Home> {
            HomeScreen(
                onOpenProfile = { userId ->
                    navController.navigate(Profile(userId = userId))
                },
            )
        }
        composable<Profile> { backStackEntry ->
            val profile = backStackEntry.toRoute<Profile>()
            ProfileScreen(
                userId = profile.userId,
                onBack = { navController.popBackStack() },
            )
        }
    }
}
```

::note
`rememberNavController()` 必须放在会跨配置变更保留的组合位置（通常是 Activity 的根内容）。不要在每个子页面各造一个 controller，否则返回栈会分裂。
::

## 在页面之间导航

调用 `navigate` 时传入路由实例。有参目的地直接构造 `data class`；无参目的地传 `object`。需要同时清栈或避免重复入栈时，在 `navigate` 的 lambda 里配置 `NavOptions`。

```kotlin [ui/home/HomeScreen.kt]
fun onOpenProfile(userId: String) {
    navController.navigate(Profile(userId = userId))
}

fun onOpenHomeAsRoot() {
    navController.navigate(Home) {
        popUpTo<Home> { inclusive = true }
        launchSingleTop = true
    }
}
```

判断当前目的地时不要再比较字符串。使用 `hasRoute`：

```kotlin [ui/scaffold/AppScaffold.kt]
import androidx.navigation.hasRoute

val isHome = navController.currentBackStackEntry
    ?.destination
    ?.hasRoute<Home>() == true
```

## 读取导航参数

### 在 Composable 中读取

在 `composable<T>` 的 lambda 里对 `NavBackStackEntry` 调用 `toRoute<T>()`，得到与路由定义一致的对象。

```kotlin [navigation/AppNavHost.kt]
composable<Profile> { backStackEntry ->
    val profile = backStackEntry.toRoute<Profile>()
    ProfileScreen(userId = profile.userId)
}
```

### 在 ViewModel 中读取

把同样的路由从 `SavedStateHandle` 解出来，进程被杀后系统恢复页面时参数仍然在。

```kotlin [ui/profile/ProfileViewModel.kt]
import androidx.lifecycle.SavedStateHandle
import androidx.lifecycle.ViewModel
import androidx.navigation.toRoute

class ProfileViewModel(
    savedStateHandle: SavedStateHandle,
) : ViewModel() {
    private val profile = savedStateHandle.toRoute<Profile>()
    val userId: String = profile.userId
}
```

::tip
Composable 和 ViewModel 都要从路由读 ID，不要一边 `toRoute()`、一边再手写 `savedStateHandle["userId"]`。两套取值方式并存时，重构参数名很容易漏改其中一处。
::

## 处理返回栈

### 弹出上一页

系统返回手势、导航栏 Up 和你自己的「返回」按钮应对齐到同一套 API：普通返回用 `popBackStack()`，工具栏 Up 用 `navigateUp()`（会考虑深层链接进入时的父图）。

```kotlin [ui/profile/ProfileScreen.kt]
fun onBack() {
    navController.popBackStack()
}

fun onNavigateUp() {
    navController.navigateUp()
}
```

### 清空返回栈后跳转

登录成功、完成引导这类「不应再回到上一页」的场景，先 `popUpTo` 起始目的地并设 `inclusive`，再 `navigate`。`launchSingleTop` 避免栈顶已经是目标时再压一层。

```kotlin [ui/login/LoginScreen.kt]
navController.navigate(Home) {
    popUpTo<Login> { inclusive = true }
    launchSingleTop = true
}
```

::warning
`popBackStack()` 在栈里只剩根目的地时会返回 `false` 且不关 Activity。根页的返回行为交给系统（预测性返回 / `OnBackPressedDispatcher`），不要在根页无条件再 pop 一次。
::

## 接入深层链接

类型安全 API 用 `navDeepLink<T>(basePath = …)` 声明 URI，路径参数与路由 `data class` 的属性对应。同时在 `AndroidManifest.xml` 为 Activity 配置相同 scheme / host 的 `intent-filter`，否则系统不会把链接交到你的 App。

```kotlin [navigation/AppNavHost.kt]
import androidx.navigation.navDeepLink

composable<Profile>(
    deepLinks = listOf(
        navDeepLink<Profile>(basePath = "https://arturoyi.dev/profile"),
    ),
) { backStackEntry ->
    val profile = backStackEntry.toRoute<Profile>()
    ProfileScreen(userId = profile.userId)
}
```

```xml [app/src/main/AndroidManifest.xml]
<activity android:name=".MainActivity">
    <intent-filter>
        <action android:name="android.intent.action.VIEW" />
        <category android:name="android.intent.category.DEFAULT" />
        <category android:name="android.intent.category.BROWSABLE" />
        <data
            android:scheme="https"
            android:host="arturoyi.dev"
            android:pathPrefix="/profile" />
    </intent-filter>
</activity>
```

::note
自定义 `NavType` 只在参数不是 Navigation 内置支持的类型时才需要。`String`、`Int`、`Boolean`、枚举走默认序列化即可；嵌套对象或列表先考虑改成 ID，而不是立刻写一套 JSON `NavType`。
::

## 实际项目：两条栈和列表-详情

记账应用的首页不是一张平铺的 `NavHost`。账单和设置是两个标签，各自记住自己走过的页面；窄屏一次只显示一页，宽屏把列表和详情并排。中间的「记一笔」不属于任何一个标签。这些用 Navigation 3 的返回栈和场景来排，版本以工程里的 `navigation3` 1.2 和 `adaptive-navigation3` 1.3 为准。

```toml [gradle/libs.versions.toml]
[versions]
nav3Core = "1.2.0"
adaptiveNavigation3 = "1.3.0"
serialization = "1.9.0"

[libraries]
androidx-navigation3-runtime = { module = "androidx.navigation3:navigation3-runtime", version.ref = "nav3Core" }
androidx-navigation3-ui = { module = "androidx.navigation3:navigation3-ui", version.ref = "nav3Core" }
androidx-adaptive-navigation3 = { group = "androidx.compose.material3.adaptive", name = "adaptive-navigation3", version.ref = "adaptiveNavigation3" }
kotlinx-serialization-json = { group = "org.jetbrains.kotlinx", name = "kotlinx-serialization-json", version.ref = "serialization" }
```

`kotlin-serialization` 插件仍然要加在定义路由的模块上。返回栈靠它在旋转和进程重建后把键还原回来。

### 每个目的地直接实现 NavKey

无参页面用 `data object`，要带进下一页的只有 ID 或类型码。键自己实现 `NavKey`，不要只在外层 `sealed interface` 上实现：还原返回栈时按具体类型找序列化器，父类型上的标记不够。

```kotlin [navigation/AppNavKey.kt]
@Serializable
internal data object Bill : NavKey

@Serializable
internal data class AddExpense(val typeCode: Int = BillType.Expense.code) : NavKey

@Serializable
internal data class BillHistory(val accountId: Long) : NavKey

@Serializable
internal data class AccountEditor(val accountId: Long? = null) : NavKey

@Serializable
internal data object SettingsList : NavKey

@Serializable
internal data object Budget : NavKey
```

`AccountEditor.accountId` 为空是新建，有值是编辑。宽屏时它是账单页旁边的详情窗格，窄屏时单独占一页。这个差别由场景决定，路由本身不分成两个目的地。

### 一个标签一条返回栈

底栏切换只改当前标签，不把另一边的页面弹掉。记一笔和设置二级页都压在**当前**标签的栈上。界面只调用三个方法：选标签、进入、返回。

```kotlin [navigation/AppNavigator.kt]
internal class AppNavigator(
    val billStack: NavBackStack<NavKey>,
    val settingsStack: NavBackStack<NavKey>,
    private val homeTabState: MutableState<HomeTab>,
) {
    val activeStack: NavBackStack<NavKey>
        get() = when (homeTab) {
            HomeTab.Bill -> billStack
            HomeTab.Settings -> settingsStack
        }

    fun selectHome(tab: HomeTab) {
        homeTab = tab
    }

    fun navigate(key: NavKey) {
        val stack = activeStack
        if (stack.lastOrNull() == key) return
        val replacesDetail = (key in settingsDetailKeys && stack.lastOrNull() in settingsDetailKeys) ||
            (key is AccountEditor && stack.lastOrNull() is AccountEditor)
        if (replacesDetail) stack[stack.lastIndex] = key else stack.add(key)
    }

    fun back() {
        if (activeStack.size > 1) activeStack.removeLastOrNull()
    }
}

@Composable
internal fun rememberAppNavigator(): AppNavigator {
    val billStack = rememberNavBackStack(Bill)
    val settingsStack = rememberNavBackStack(SettingsList)
    val homeTab = rememberSaveable { mutableStateOf(HomeTab.Bill) }
    return remember(billStack, settingsStack, homeTab) {
        AppNavigator(billStack, settingsStack, homeTab)
    }
}
```

设置里的外观、备份、统计、预算彼此是同一层详情。再点另一项时替换栈顶，返回直接回到设置列表。账户编辑同理：从「新建」换成「编辑另一个」时替换，不在栈里叠两张表单。已经在栈顶的同一个键直接忽略，避免连点压出两页。

栈里只剩标签起点时，`back()` 直接返回。系统返回由 `NavigationBackHandler` 交给这个 `back()`；根页面留在栈里，结束 Activity 的手势仍然归系统。

### 路由表只绑定一次界面

`entryProvider` 里每个键对应一个入口。页面通过回调把下一跳交回 `AppNavigator`，自己不持有返回栈。

```kotlin [navigation/AppRouteTable.kt]
internal fun EntryProviderScope<NavKey>.appRoutes(navigator: AppNavigator) {
    entry<Bill>(
        metadata = ListDetailSceneStrategy.listPane(
            detailPlaceholder = { AccountDetailPlaceholder() },
        ) + homeTabMetadata(),
    ) {
        BillRoute(
            onCreateAccount = { navigator.navigate(AccountEditor()) },
            onEditAccount = { id -> navigator.navigate(AccountEditor(id)) },
            onViewAll = { id -> navigator.navigate(BillHistory(id)) },
            onOpenBudget = { navigator.navigate(Budget) },
        )
    }
    entry<BillHistory> { key ->
        BillHistoryRoute(
            accountId = key.accountId,
            onBack = dropUnlessResumed(block = navigator::back),
        )
    }
    entry<AccountEditor>(metadata = ListDetailSceneStrategy.detailPane()) { key ->
        AccountEditorRoute(
            accountId = key.accountId,
            onBack = dropUnlessResumed(block = navigator::back),
        )
    }
}
```

`entry` 的 lambda 参数就是那个键，参数从这里拆开传给页面。Navigation 3 这条链上不必再 `toRoute()`。

`dropUnlessResumed` 包住返回和列表点击。转场过程中当前页还没回到 `RESUMED`，这次点击会被丢掉，侧滑没结束时不会连开两页。

### 宽屏并排，窄屏整页滑

场景策略看窗口：放得下两栏时，带 `listPane` 的账单或设置留在左边，带 `detailPane` 的账户表单或统计留在右边；放不下一栏时退回单页。占位内容只在还没有详情时显示。

```kotlin [navigation/AppNavHost.kt]
@Composable
internal fun rememberAppSceneState(navigator: AppNavigator): SceneState<NavKey> {
    val provider = entryProvider<NavKey> { appRoutes(navigator) }
    val billEntries = rememberHomeEntries(navigator.billStack, provider)
    val settingsEntries = rememberHomeEntries(navigator.settingsStack, provider)
    val entries = when (navigator.homeTab) {
        HomeTab.Bill -> billEntries
        HomeTab.Settings -> settingsEntries
    }
    return rememberSceneState(
        entries = entries,
        sceneStrategies = listOf(rememberListDetailSceneStrategy()),
        onBack = navigator::back,
    )
}
```

两条栈都会做装饰，包括当前没显示的那条。切回另一个标签时，滚动位置和 `rememberSaveable` 的表单还在。只装饰正在显示的栈，切走再回来会重新组合，列表回到顶部。

装饰里至少留 `rememberSaveableStateHolderNavEntryDecorator()`。每个目的地外面再包一层主题纯色，侧滑时这一层跟着页面走，当前页不会透出上一页。

窄屏的推入按微信的方式：新页从末端滑入，旧页让出大约四分之一宽度，时长 280ms，不做淡入淡出，也不改容器尺寸。两个首页标签对调时两边都还带着首页标记，这条切换用空转场，账单和设置不会互相推开。宽屏列表-详情由场景自己排，不走整页滑动。

底栏是否出现，看**当前场景里还有没有首页目的地**，不看栈顶。宽屏并排时栈顶已经是统计或账户表单，左边的列表仍是首页，侧栏要留着。首页标记写在 `Bill` 和 `SettingsList` 的 metadata 上，场景里任一入口带这个标记就显示导航条。

### 参数怎么进 ViewModel

入口把 `accountId`、`typeCode` 交给页面的 Route。Route 再用带这个参数的工厂创建 ViewModel。这个工程没有给每个入口单独挂 `rememberViewModelStoreNavEntryDecorator()`，`viewModel()` 落在 Activity 上，所以同一类 ViewModel 要靠 `key` 区分实例。

```kotlin [feature/bill/account/AccountEditorScreen.kt]
viewModel: AccountEditorViewModel = viewModel(
    key = "account-editor-${accountId ?: "new"}",
    factory = AccountEditorViewModel.factory(accountId),
)
```

key 里带上会变化的那一段。工厂只在这个 key 第一次创建时执行，之后再进同一类页面会拿到上次的实例。记一笔用 `"add-expense-$typeCode"`。账单首页在自己的 Route 里先把这个 ViewModel 订上，用户点加号时分类和账户已经在状态里。

::warning
全部账单的 Route 目前只按类型取 ViewModel，没有把 `accountId` 写进 key。换一个账户再打开「查看全部」时，工厂不会重跑，列表仍是上一个账户。新页面要沿账户编辑这条，把参数放进 key。
::

保存完成是一次性结果，用 `SharedFlow` 通知 Route，Route 再调用 `onBack`。ViewModel 不持有 `AppNavigator`。

### 和前半篇怎么选

单 Activity、一张图、没有分栏时，前半的 `NavHost` 和 `composable<T>` 足够，参数继续用 `toRoute()`。出现下面任一情况时，再换成这一节的返回栈和场景：

- 底栏或侧栏有多个标签，每个标签要记住自己的返回栈
- 手机上一页一页滑，平板上列表和详情并排，而且是同一个目的地
- 切走的页面必须留着滚动和表单，不能只靠当前栈顶那一个 `NavBackStackEntry`
